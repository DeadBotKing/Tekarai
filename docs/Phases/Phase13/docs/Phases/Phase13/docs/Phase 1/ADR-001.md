# ADR-001 — Tekarai as Enterprise Operations Platform

Status: ACCEPTED
Date: 2026-08-29
Author: Tekarai Team

## Context
Tekarai is a multi-module enterprise operations platform (rebranded from Meryx). It serves identity, organization, workforce, project, task, asset, device, maintenance, document, workflow, communication, notification, audit, reporting, AI, integration, configuration, and platform core.

## Decision
- Use modular monolith architecture (ADR-002).
- Use clean architecture / domain-driven design (ADR-003 / ADR-004).
- Use multi-tenant design (ADR-007).
- Use SQL Server + Django ORM + mssql-django (Phase 4 / Phase 19).
- Preserve framework identifiers exactly: INSTALLED_APPS, SECRET_KEY, MEDIA_ROOT, ROOT_URLCONF, EMAIL_BACKEND, select_related, prefetch_related, select_for_update, SET_NULL, SET_DEFAULT, is_staff, is_superuser, node_modules.
- Apply camelCase to all project-specific identifiers (createdAt, tenantId, conversationId, dbHost, jwtSigningKey, etc.).
- Preserve real API identifiers exactly.

## Consequences
- All phases (1-20) reference this ADR.
- Communication contradictions resolved via CanonicalCommunication.md.
- Notification contradictions resolved via CanonicalNotification.md.
